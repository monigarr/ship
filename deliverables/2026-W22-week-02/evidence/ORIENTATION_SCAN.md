## Summary

This repository is Ship, a large `pnpm` monorepo for a document-first project management and accountability application. The product centers on planning, execution tracking, documentation, weekly accountability workflows, collaborative editing, and FleetGraph project-intelligence features.

The core model is unified around documents: issues, projects, programs, weeks/sprints, people, weekly plans, retrospectives, standups, reviews, and wiki pages all use the same broad document model with typed properties and associations.

## Repository Shape

- `api/`: Express and PostgreSQL backend with REST routes, OpenAPI/Swagger docs, auth/session handling, CSRF protection, rate limiting, WebSocket collaboration, AI analysis, accountability routes, and FleetGraph services.
- `web/`: React and Vite frontend with TanStack Query, TipTap/Yjs collaborative editing, context sidebars, dashboards, document pages, issue/project/program views, team views, and FleetGraph trace pages.
- `shared/`: Shared TypeScript types, constants, and contracts used by both API and web packages.
- `e2e/`: Playwright end-to-end tests. The test setup uses isolated Postgres/API/web environments per worker.
- `docs/`: Architecture, workflow, model, operational, and solution documentation.
- `terraform/`: AWS infrastructure modules and environment definitions.
- `prd_dev_branch_one/`: PRD from GFA2 Week 4, audit, evidence, and branch deliverable artifacts.
- `ship-compliance/`: Python compliance tooling and tests.

## Main Technologies

- **Workspace/package manager**: `pnpm`
- **Backend**: Node.js, Express, PostgreSQL via `pg`
- **Frontend**: React, Vite, React Router, Tailwind, Radix-style UI patterns
- **Editor/collaboration**: TipTap, Yjs, `y-websocket`, `y-indexeddb`
- **Server state**: TanStack Query with IndexedDB persistence
- **Tests**: Vitest for unit/integration, Playwright for E2E
- **Deployment**: Docker, Render blueprint, Terraform for AWS infrastructure paths

## Backend Orientation

The API entry points are:

- `api/src/index.ts`: loads environment, creates the HTTP server, attaches collaboration WebSockets, starts the FleetGraph proactive scheduler, and listens on the configured port.
- `api/src/app.ts`: constructs the Express app, configures security middleware, sessions, CSRF, rate limits, Swagger, and all REST route mounts.

Important backend areas:

- `api/src/routes/`: REST endpoints for auth, documents, issues, projects, programs, weeks, standups, team, workspaces, admin, files, comments, dashboard, accountability, AI, and FleetGraph.
- `api/src/db/schema.sql`: base schema for workspaces, users, memberships, sessions, documents, document associations, history, snapshots, files, comments, API tokens, and iteration tracking.
- `api/src/db/migrations/`: SQL migrations that evolve the schema.
- `api/src/collaboration/index.ts`: Yjs WebSocket collaboration server, awareness/presence, persistence to Postgres, cache invalidation, visibility enforcement, and realtime event sockets.
- `api/src/services/fleetgraph/`: FleetGraph runtime, proactive scheduler, trace persistence, notifications, HITL actions, and synthesis.

The API uses session-based browser authentication, CSRF protection for state-changing session requests, and skips CSRF for Bearer API-token requests. Production startup can load secrets from SSM, while Render deployment skips SSM via environment configuration.

## Data Model

The central model is a `documents` table and shared `DocumentType` union. Current document types include:

- `wiki`
- `issue`
- `program`
- `project`
- `sprint`
- `person`
- `weekly_plan`
- `weekly_retro`
- `standup`
- `weekly_review`

Relationships use `document_associations` and typed `belongs_to` style references rather than many separate foreign-key columns. Document content is stored as JSON and, for collaborative editing, also as Yjs state. Document history and snapshots provide auditability for important content changes.

Issue properties include state, priority, assignee, estimate, source, due date, and accountability metadata. Project and program properties include visual metadata and RACI-style ownership fields. Weekly plan and retro documents are tied to a person and week number.

## FleetGraph

FleetGraph is an internal project intelligence agent for Ship. It monitors planning quality, stale execution, missing evidence, accountability gaps, approval gaps, and compliance/security risks.

Key implementation locations:

- `api/src/services/fleetgraph/runtime.ts`
- `api/src/services/fleetgraph/proactive.ts`
- `api/src/services/fleetgraph/trace.ts`
- `api/src/services/fleetgraph/notifications.ts`
- `api/src/routes/fleetgraph.ts`
- `web/src/pages/FleetGraphTracesPage.tsx`
- `web/src/pages/FleetGraphTracePage.tsx`
- FleetGraph assistant UI in contextual sidebars

FleetGraph supports on-demand context-aware runs and proactive scans. It records internal trace data in Ship and exposes authenticated trace URLs under `/fleetgraph/traces/:traceId`. Human-in-the-loop approval is required for sensitive or mutating actions.

## Local Development

The README documents the primary local workflow:

```powershell
pnpm install
pnpm dev
```

`pnpm dev` runs `scripts/dev.sh`, which creates local environment defaults, prepares a worktree-specific database when needed, finds available API/web ports, and starts API and web together.

Expected local URLs:

- **Web app**: `http://localhost:5173` or the next available `517x` port
- **API**: `http://localhost:3000` or the next available `300x` port
- **Swagger UI**: `<api-url>/api/docs`
- **OpenAPI JSON**: `<api-url>/api/openapi.json`

Docker local stack:

```powershell
pnpm docker:up
```

This uses `docker-compose.local.yml` and starts Postgres, API, and web containers.

## Initial Assessment

Ship is a mature, actively worked monorepo rather than a small starter app. The codebase has substantial product surface area, including collaboration, accountability workflows, admin/workspace management, file uploads, team allocation, project/program planning, weekly rituals, FleetGraph analysis, and internal observability.

The highest-value mental model is:

1. Ship is a document-first system.
2. The backend is a single Express/Postgres app with WebSocket collaboration attached.
3. The frontend is a React/Vite app with a persistent app shell and unified document route.
4. FleetGraph is implemented inside Ship rather than as a separate external tracing or agent platform.
5. Tests and docs are extensive, but generated/evidence artifacts add significant repo noise.
